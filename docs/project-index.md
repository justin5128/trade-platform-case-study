# Project index

[Flagship overview](../README.md) · [Product journey](portfolio.md) · [Delivery approach](delivery-playbook.md)

This index accounts for the development work identified in the available local workspace, connected project listings and Drive inventory. It groups components into product workstreams so a reader can follow complete problems rather than a list of scripts. It is not an assertion that every historical project has been recovered.

## Evidence key

**Development record:** implementation artifacts and a recorded iteration history were reviewed. **Artifact:** a workbook, service, interface or template exists; operational success is not inferred. **Design / feasibility:** a mockup or technical exploration exists. **Exploration:** a project direction is recorded; a functioning deployment is not established.

The linked narratives add newly authored public requirements and design reasoning. These are labeled as proposals where they go beyond the evidence.

## Coverage decisions

Private analytical work is represented only as a **Proprietary Analysis Layer**. Internal variants, names, relationships and methods are intentionally not enumerated. They are not missing public features.

Personal administration, employment documents and general conversations are not treated as software projects. A title alone is insufficient evidence of a built product. New discoveries should enter this register with their evidence level before receiving a public case study.

## Why six repositories

The flagship carries the end-to-end story. The remaining five give a reviewer depth in integrations, data, UX, architecture and specifications. Content automation and backup tooling receive substantive documentation within those themes, preserving a focused recruiter experience while broadening project coverage.
